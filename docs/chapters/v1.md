# v1 — Tách quyền sở hữu dữ liệu

## Mục tiêu
Tách catalog, đơn hàng và tài khoản khỏi một model EF chung để mỗi miền có thể thay đổi
schema độc lập. Web/Admin vẫn truy cập database trực tiếp; chưa tách API ở chương này.

## Trước / Sau
Trước: Web MVC và Admin Blazor dùng `StoreDbContext` → `storedb`.
Sau: cả hai ứng dụng sử dụng ba đường truy cập riêng:

```text
Web / Admin → CatalogDbContext  → catalogdb  (Categories, Products)
Web / Admin → OrderDbContext    → orderdb    (Orders, OrderItems)
Web / Admin → IdentityDbContext → identitydb (ASP.NET Core Identity)
```

Ba database vẫn cùng PostgreSQL instance. Đây là tách ranh giới dữ liệu, chưa phải ba
service triển khai độc lập. Mã monolith đã có trong commit `97ec50f` trước chương này;
commit đó chưa có tag/ghi chú v0 theo quy trình. v1 giữ nguyên lịch sử có sẵn.

## Những gì thay đổi
- Thay `StoreDbContext` và hai factory cũ bằng ba context và ba design-time factory.
- Thay migration monolith bằng ba chuỗi khởi tạo ở `Migrations/Catalog`, `Migrations/Order`,
  `Migrations/Identity`. Mỗi context có snapshot riêng; Identity giữ schema Version3/passkeys.
- `OrderItem.ProductId` chỉ là mã tham chiếu; bỏ navigation `Product`, thêm `ProductName`.
  Khi đặt hàng, sao chép tên và giá từ giỏ hàng. Trang đơn hàng chỉ đọc dữ liệu orderdb.
- Catalog/Cart dùng CatalogDbContext; OrderService dùng OrderDbContext; Identity stores dùng
  IdentityDbContext. Admin inject đúng context cho mỗi trang, ghép dữ liệu khách/đơn trong bộ nhớ.
- AppHost cấp ba database và truyền cả ba connection strings cho Web/Admin. Web migrate
  và seed lúc khởi động. Các project placeholder vẫn biên dịch, không thêm chức năng v2.
- README, ROADMAP và hướng dẫn secrets phản ánh trạng thái v1.

## Quyết định thiết kế và đánh đổi (trade-off)
**Mỗi miền có migration riêng.** Đổi độ chính xác giá sản phẩm chỉ tác động catalogdb;
không phải kéo schema tài khoản đi cùng. Đổi lại phải quản lý ba kết nối và ba migration history.
Cùng một PostgreSQL instance giúp học đơn giản hơn, nhưng chưa cô lập tài nguyên hay quyền DB
hoàn toàn: Web và Admin hiện vẫn được truy cập cả ba.

**Đơn hàng giữ snapshot tên sản phẩm.** Ví dụ mua “Wireless Headphones”, sau đó cửa hàng
đổi tên sản phẩm: hóa đơn cũ vẫn giữ tên đã mua. Dữ liệu bị lặp có chủ ý; không đồng bộ tên
mới vào đơn cũ. Nếu tiếp tục giữ navigation Product, EF có thể kéo bảng Products vào model
Order và phá ranh giới vừa tách. ProductId và UserId là soft reference; database không còn
kiểm tra sự tồn tại của bản ghi ở miền khác.

**Ghép dữ liệu tại ứng dụng.** Trang Customers truy vấn số đơn theo UserId từ orderdb,
đọc danh sách tài khoản từ identitydb rồi ghép bằng dictionary. Không có SQL join xuyên DB.
Cách này dễ thấy phụ thuộc nhưng cần nhiều truy vấn, tốn bộ nhớ và không có snapshot giao dịch
chung giữa ba database. Nếu giữ một DB thì join thuận tiện hơn nhưng coupling vẫn còn.

**Khởi tạo database mới.** Các migration v1 không phải công cụ chuyển dữ liệu v0.
Không xóa hoặc sửa `storedb`; dữ liệu cũ không tự xuất hiện trong ba DB mới. Muốn chuyển dữ liệu
thật cần kế hoạch riêng để giữ khóa, sao chép tài khoản và tạo snapshot tên cho đơn cũ.
Có thể xem lại migration cũ ở commit `97ec50f`.

**Chỉ Web migrate/seed.** Tránh để cả hai frontend cùng seed khi khởi động; phải chờ Web
khởi tạo trước khi dùng Admin. Một migration runner riêng là lựa chọn khác nhưng chưa cần
thêm vào phạm vi chương này. Các factory chỉ dùng cấu hình không mật khẩu để sinh schema;
`database update` cần connection string môi trường đúng database đích.

Thiết kế tham khảo: [ghi chú v1 upstream](https://github.com/daohainam/simple-store/blob/1b1ef8cbce79ba9ce16764c0501135e871e66b91/docs/v1-changes.md)
(MIT, Dao Hai Nam). Bản dựng giữ hỗ trợ passkey đã có trong mã nền.

## Cách kiểm tra

```bash
dotnet build SimpleStore.slnx -c Release
dotnet tool install dotnet-ef --version 10.0.7 --tool-path /tmp/simplestore-tools

for context in Catalog Order Identity; do
  /tmp/simplestore-tools/dotnet-ef migrations has-pending-model-changes \
    --project src/SimpleStore.Data --context "${context}DbContext" --configuration Release
  /tmp/simplestore-tools/dotnet-ef migrations script \
    --project src/SimpleStore.Data --context "${context}DbContext" --configuration Release \
    --output "/tmp/${context}.sql"
done

dotnet run --project src/SimpleStore.AppHost --launch-profile http
```

Khi thêm migration mới, luôn chỉ định `--context` và `--output-dir Migrations/<miền>`.
Nếu chạy riêng Web/Admin, cung cấp `ConnectionStrings__catalogdb`, `ConnectionStrings__orderdb`,
`ConnectionStrings__identitydb` bằng môi trường hoặc user-secrets của ứng dụng.

1. Chờ Web migrate/seed, mở catalog và đăng nhập tài khoản demo trong README.
2. Thêm sản phẩm vào giỏ, đặt hàng; kiểm tra trang xác nhận, danh sách và chi tiết đơn.
3. Đổi tên sản phẩm trong catalog; đơn đã đặt vẫn giữ tên cũ.
4. Mở Admin: dashboard, products, categories, customers, orders; đối chiếu số đơn của khách.
5. Kiểm tra schema: catalogdb chỉ có Categories/Products, orderdb chỉ có Orders/OrderItems,
   identitydb chỉ có các bảng Identity; mỗi DB có `__EFMigrationsHistory` riêng.
   FK nghiệp vụ chỉ gồm Products → Categories và OrderItems → Orders.

Kết quả thực tế của lượt triển khai:
- Build Release toàn bộ 20 project: **0 lỗi**, 24 cảnh báo NU1902/NU1903 về MessagePack 2.5.192
  từ dependency hiện có; giữ phiên bản package trong phạm vi v1.
- Cả ba context không có pending model changes; sinh SQL migration độc lập thành công.
- Dùng PostgreSQL 17 tạm trên loopback, cổng 55439, database trắng: Web migrate cả ba DB,
  seed catalog/Identity thành công; xác nhận schema và FK bằng truy vấn PostgreSQL.
- Smoke HTTP đăng nhập demo → giỏ hàng → checkout → confirmation/details/list thành công.
  Đổi tên sản phẩm bằng SQL trong DB tạm: catalog hiển thị tên mới, đơn vẫn giữ tên cũ.
- Năm trang Admin render HTTP 200 và đọc đúng dữ liệu từ ba DB.
- **Chưa kiểm tra** AppHost/container vì không có Docker; chưa thao tác CRUD qua tương tác
  Blazor, chưa thử thiết bị passkey hoặc khởi động lại toàn bộ hệ thống. HTTP Admin ở đây
  chỉ xác nhận phần render ban đầu và truy vấn dữ liệu.
